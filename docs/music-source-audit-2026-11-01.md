# 音源检查 — 2026-11-01

## 范围与结论

检查本地当前源码（v0.6.9 加尚未发布的 QQ 搜索修复）、127.0.0.1:8080 音源服务。使用内存数据库，不加载 .env、不读写真实账号、平台登录凭据或歌单。没有更新 Release、APK 或服务器。

覆盖十个单曲搜索源；汽水按产品约定不提供单曲搜索，未做 DRM、会员绕过或加密播放测试。本地音源服务二进制未证明与已发布 APK 完全一致。手机路由验证是在 Node 中切换手机配置，不等于 Android 原生网络、后台或真机听感验收。

结论：仍有问题。搜索、上游探测成功和真实音频响应必须分开判断。以下是有限样本，不能将单首失败推广成整个平台不可用。

## 确认的代码问题与优先级

### P1：备用服务的熔断状态跨音源共用

位置：src/server/goMusicApi.ts 的 consecutiveFailures/unavailableUntil、fetchJson、searchWithGoMusicApi。

独立固定夹具复现：对酷狗注入两次请求异常；随后给千千提供保证成功的 mock，预期调用一次并返回一首，实际调用零次、返回零首。当前状态把上游单源超时与整个服务不可达混在一起，桌面会暂停所有备用源 60 秒。手机配置绕过该退避，并不能说明桌面问题已解决。

建议：按操作/音源隔离上游失败；只有确认音源服务本身不可达时才使用服务级熔断。增加“某源失败不阻断另一源”的回归。不可用应留有内部诊断，不直接渲染原始上游错误给用户。

### P1：只相信 inspect.valid，未验证随后返回的媒体

位置：src/server/goMusicApi.ts 的 validateCandidate、resolveExactWithGoMusicApi；src/server/app.ts 的 /api/backup-media。

上游 InspectMusic 只凭 200/206 判 valid=true，没有验证内容。小屋接受该标志，备用媒体转发也仅检查状态和 body。真实样本出现咪咕 JSON 200、网易云探测成功后流 404。

建议：实际解析阶段做有上限的 Range 检查，检查状态、内容签名和合理长度；拒绝 JSON、网页和限制提示音；MIME 异常但签名为有效音频时有明确处理规则。媒体失败后只尝试严格身份匹配的替代，不能标记原音源播放成功。需同时验证 Android 直连路径，不能只修网页代理。

### P2：元数据缺失降低版本、时长核验能力

真实样本：网易云和咪咕多条 duration=0。0 代表未知，不能当有效时长；Bilibili 标题和上传者也不能视为完整原唱元数据。

建议：补充来自平台详情的身份及时长证据；证据不足时保持不可自动替代或要求用户选择。不可用推测值、模型生成的时长或宽松歌手匹配填补缺口。

### P2：搜索目录过滤仍存在于其他上游平台

已查源码：music-lib qianqian/song.go Search 对 isVip!=0 的条目 continue。QQ 的元数据过滤已在 v0.6.9 Android 构建补丁中移除，但运行中的本地 8080 是另一份二进制，不能认为已经更新。

建议：逐平台区分“目录可展示”与“音频可授权播放”，不要用付费元数据过滤冒充无搜索结果。先保留可验证 ID，再由实际播放授权决定能否播放。
