# Windows 桌面首版验收

日期：2026-11-03。基于 v0.7.3；用户要求安卓发布后制作 Windows 安装包，随后要求继续完成。

## 结果

- 独立 Electron 窗口、内置 Node 24.21.0、现有 Go 音源服务、每用户 NSIS x64 安装器。
- 不使用开发服务器 3000；后台监听本机随机端口，当前 UI 实测为独立回环地址。所有后台启动使用隐藏窗口。
- 数据放置在 `%APPDATA%\MusicHouse`，与安装目录分离；单实例，重复启动激活原窗口，关闭窗口退出本应用启动的后台进程。
- 复用已有8080音源服务时不关闭它；没有更改系统代理或原3000服务。
- 使用沙箱、上下文隔离、禁用渲染器Node权限，限制站内导航，外部网页交给系统浏览器；同源下载沿用窗口会话。

## 证据

- Android v0.7.3 已单独发布，main/tag f0f24a5。桌面构建没有改变该标签。
- `node desktop/smoke-runtime.mjs`：在临时目录用内置Node启动，健康/HTML通过；注册临时账户、创建歌单、正常停止、重启、登录、读取同一歌单，全部断言通过。
- 实际打包后的 Windows 程序成功打开独立登录页；截图在私有 `data/windows/windows-first-launch.png`。没有操作用户原有Edge播放窗口或真实账户。
- 关闭桌面窗口后，打包目录内的应用和Node进程均退出；未停止原有8080服务。
- 分发按白名单复制编译结果与Git中已提交的公共素材，生产依赖独立安装；不带 `.env`、用户数据库、模型密钥、未知本地图片和本地交接。Node与项目第三方许可随包附带。

## 限制

- 这次只制作本地Windows安装包，没有把Windows包上传GitHub或云服务器。
- 没有Windows代码签名证书，安装器可能提示未知发布者。未执行安装器安装/覆盖升级/卸载演练，不能以服务重启持久化测试替代安装器升级实测。
- 首次使用独立账户与数据，可通过现有音乐备份恢复导入网页资料；不自动迁移本机真实数据。
- 未实测真实音源听感、下载落盘、系统媒体键、睡眠唤醒及语音输入；首版麦克风权限默认拒绝。没有托盘常驻或自动更新。
